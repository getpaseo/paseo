# v0.2.5 Worktree Repository Identity Provenance

## Purpose

This change makes legacy `paseo worktree` operations safe when the CLI connects to
a daemon on another machine. The daemon selects a registered repository before it
lists, creates, or archives a worktree. It does not use the CLI process current
directory as a remote filesystem path.

## Upstream Conditions

- Preserve wire parsing for legacy optional `cwd` fields until 2027-02-01.
- The daemon must reject a request with no `projectId` or `repoRoot` identity.
- The daemon accepts only an active registered project root after canonical path
  resolution. It rejects missing roots, traversal, symlink escapes, and archived
  projects.
- Archive targets must canonically match exactly one worktree reported for the
  selected repository.
- The client requires `server_info.features.worktreeRepositoryIdentity`; an older
  daemon receives the upgrade guidance instead of a fallback request.
- The CLI may infer `process.cwd()` only after the connected daemon reports the
  same hostname as the CLI host. Remote calls require `--project` or `--repo-root`.

## Drop Conditions

- Remove legacy `cwd` parsing and the client feature gate no earlier than
  2027-02-01, after the compatible daemon floor is confirmed.
- Keep the explicit repository identity requirement after the compatibility code
  is removed.
