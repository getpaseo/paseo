Save environment variables once per project and let agents use them in commands and API requests. Open **Project environment** from the Command Center to add a name, value, and optional description. Git worktrees share their project's variables. Non-Git directories each have their own variables.

Agents get two tools: one lists names and descriptions without values; the other runs a shell command with the variables it requests. Values are read at execution time, so additions, replacements, and removals take effect on the next command without reopening the agent. New agents receive the tools and usage instructions automatically. Agents created before installation need their MCP configuration updated once; changing values afterward does not require a refresh. Ordinary provider shell commands and existing terminals do not receive these variables.

Requires Paseo 0.13.2 and a macOS or Linux daemon. Variables are stored as plaintext JSON under `$PASEO_HOME/plugin-data/project-environment`, outside the project, with owner-only directory and file permissions. Values are never returned by the management UI or metadata tool. Saved values remain after plugin removal; delete them through the panel before removing the plugin if you want to discard them.

Commands run as the daemon user in the connected workspace, with host filesystem and network access. Only requested project variables and a small set of basic shell environment variables are passed to the command. Commands have a maximum two-minute deadline, four concurrent MCP requests, and a combined 1 MiB output limit. Background services and interactive input are unsupported.

Exact project variable values are replaced with `[REDACTED]` in returned output. Output from stopped commands is withheld. Encoded or transformed values are not detected. This is protection against accidental disclosure, not an operating-system sandbox: commands can write or transmit credentials and perform whatever API operations those credentials allow. API responses returned by a command enter the agent's conversation and may be sent to its model provider.

The MCP broker listens only on loopback, rejects browser origins, and uses a separate random capability URL for each workspace directory. Anyone with that URL and local host access can invoke its tools. The project variables and broker credentials are accessible to the daemon user and administrators. Credentials are not isolated from agents with equivalent filesystem access.
